# Финальная презентация — структура (Неделя 7)

Ориентировочно 10–12 слайдов, защита ~10 минут + вопросы.

## Слайд 1 — Титул
- Название: «Online Subscription System for Small Business»
- Команда, дисциплина, дата
- Стек одной строкой: FastAPI · PostgreSQL · Docker

## Слайд 2 — Проблема и решение
- Малому бизнесу сложно вручную вести подписки клиентов (даты, статусы, тарифы).
- Наше решение: B2B-инструмент с API для управления подписками и ролями.

## Слайд 3 — Целевые роли
- Admin (владелец/менеджер) — полный доступ.
- Employee (поддержка/продажи) — создание и обновление.
- End-Customer — просмотр своего профиля.

## Слайд 4 — Архитектура
- Слоистая структура: routes → schemas (валидация) → models (ORM) → PostgreSQL.
- Диаграмма: Frontend → FastAPI (JWT) → SQLAlchemy → PostgreSQL.

## Слайд 5 — Схема базы данных
- ERD из 5 таблиц (companies, users, plans, customers, subscriptions).
- Подчеркнуть связи и правила CASCADE / RESTRICT.

## Слайд 6 — Безопасность
- JWT-аутентификация, bcrypt-хэши.
- RBAC: кто что может (таблица доступа).

## Слайд 7 — Валидация и обработка ошибок
- Pydantic: email, `end_date > start_date`, цена ≥ 0.
- Коды ответов: 400 / 401 / 403 / 404 / 422.

## Слайд 8 — Демонстрация API (live)
- Swagger `/docs`: логин → создание подписки → отчёт по активным подпискам (JOIN).
- Показать ответ 403 при попытке employee удалить подписку.

## Слайд 9 — Деплой
- Docker + docker-compose (web + PostgreSQL).
- Render/Railway, переменные окружения, секреты в `.env`.

## Слайд 10 — Итоги и развитие
- Что сделано; возможные доработки: платежи (Stripe), уведомления, авто-смена статуса по дате, Alembic-миграции, тесты pytest.

## Слайд 11 — Распределение работы в команде
- Кто за что отвечал.
